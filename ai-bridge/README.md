# ai-bridge

게임과 생성형 AI를 연결하는 Python 프로그램입니다. AI가 **게임 화면을 보고 키보드·마우스로** 녹픽던을 플레이하고, 그 판단을 웹 화면에서 지켜볼 수 있어요.

| 파일 | 역할 |
|---|---|
| `web.py` | **관찰 웹 화면** (설정 → 관찰 → 리포트) |
| `agent.py` | AI 플레이어 핵심 로직 (화면 캡처, AI 호출(Claude / OpenAI), 입력, 기록) |
| `input_lock.py` | 두 창 화면에서 실행 중 게임 창의 **사람 입력 잠금** (AI 입력은 통과) |
| `window_layout.py` | 두 창 배치(게임 왼쪽 + 관찰 패널 오른쪽), 관찰 패널을 주소창 없는 앱 창으로 띄우기 |
| `mvp.py` | 웹 화면 없이 콘솔에서 바로 실행 |
| `guide.md` | 공략 문서 (설정에서 "공략 제공"을 고르면 AI에게 전달) |
| `test_connection.py` | API 연결 확인 (`.env`에 키가 있는 회사마다, 또는 `python test_connection.py gpt-6-luna`처럼 모델 하나) |
| `web/` | 웹 화면 파일 (HTML, CSS, JS) |

> 실제 플레이는 **Windows 전용**이에요. 데모 모드는 어디서나 돼요.

## 준비

1. [Python 3.10 이상](https://www.python.org/downloads/) 설치 (설치할 때 **Add python.exe to PATH** 체크)
2. 이 폴더에서 필요한 라이브러리 설치
   ```bash
   pip install -r requirements.txt
   ```
3. 쓰려는 모델 회사의 API 키 발급 (크레딧 충전 필요). 둘 중 하나만 있어도 돼요
   - Claude 모델: [Claude Console](https://console.anthropic.com/) → `.env`의 `ANTHROPIC_API_KEY`
   - GPT 모델: [OpenAI Platform](https://platform.openai.com/api-keys) → `.env`의 `OPENAI_API_KEY`
   - 키는 게임의 **AI 설정** 장면에서 [키 입력]으로 넣어요. 고른 모델 회사의 이름(`OPENAI_API_KEY` 등)으로 `.env`에 한 줄만 저장돼요. `.env.example`을 `.env`로 복사해 직접 적어도 돼요
   > ⚠️ `.env`는 `.gitignore`에 들어 있어서 GitHub에 올라가지 않아요.

## 모델

| 회사 | 모델 | 입력 / 출력 ($/100만 토큰) |
|---|---|---|
| Claude | Haiku 4.5 (기본값) / Sonnet 5.5 / Opus 5.5 | 1 / 5 · 2 / 10 · 4 / 20 |
| OpenAI | GPT-6 Luna / GPT-6.1 Sol / GPT-6 Astra | 0.1 / 0.5 · 2 / 10 · 10 / 50 |

- 게임의 AI 설정에서는 Python이 보내 준 목록(`agent.py`의 `MODELS`)에서 골라요.
- 명령줄에서는 `--model gpt-6-luna`처럼 고르고, 안 고르면 `.env`의 `MODEL`(직접 적었을 때만), 그것도 없으면 Haiku 4.5를 써요. 웹 화면은 이제 `.env`에 `MODEL`을 쓰지 않아요.
- OpenAI 모델은 답하기 전에 속으로 생각하는 추론 단계가 있어서 강도를 `low`로 두었어요. 추론 토큰도 출력 요금으로 계산돼요.
- 두 회사의 차이: OpenAI 모델은 생각을 도구 안의 `thought` 칸에 쓰고, 도구를 반드시 하나 쓰게 했어요(Claude는 생각을 글로 쓰고 도구를 고름). 규칙(시스템 프롬프트)과 도구의 나머지 칸은 같아요. 관찰 화면·기록에서 어떻게 보이는지는 [시스템 구조 문서](../docs/project/architecture.md#회사별-생각-전달-방식)에 정리했어요.

## 실행

### 1. 먼저 데모로 화면 둘러보기 (게임·API 필요 없음)
```bash
python web.py --demo
```
브라우저가 열리면 실험 설정(데모 전용 화면)에서 이름만 넣고 **던전 입장**. 가짜 판단으로 관찰 화면과 리포트가 어떻게 움직이는지 볼 수 있어요.

### 2. 게임의 AI 설정에서 판 시작하기
1. 게임을 켜고(`gradlew.bat desktop:debug`) 캐릭터 선택 → **시작** → **AI 설정** 장면
2. 관찰기가 꺼져 있으면 **[AI 관찰기 켜기]** 를 눌러요. 새 명령 창에서 `python web.py --panels`가 켜지고 저절로 이어져요 (직접 `python web.py --panels`를 먼저 켜 둬도 돼요)
3. 모델을 고르고 **[키 입력]**(처음 한 번) → **[연결 시험]** → **[AI로 시작]**
   - 연결 시험은 고른 모델로 아주 짧게 한 번 불러요 (비용이 조금 들어요). `web.py`를 다시 켜면 다시 시험해야 해요
   - 게임에서 시작하는 판은 언제나 **실제 조작**이에요. 생각만 하기는 명령줄 `python mvp.py --dry-run`으로 해요
   - [AI로 시작]을 누르면 `logs/run_…/config.json`이 게임에서 고른 값으로 생기고 던전에 들어가요. 관찰 패널에는 "던전 도착을 기다리는 중"이 보여요
   - 첫 판 튜토리얼이 남아 있으면 [AI로 시작]이 회색이에요. [AI 없이 시작]으로 튜토리얼을 한 번 마쳐 주세요
4. 던전 1층에 도착하면 **AI가 스스로 시작해요** (사람은 아무것도 누르지 않아요). 층을 옮겨도 새로 시작하지 않아요
5. 판이 끝나면 AI도 멈추고 입력 잠금이 풀려요: 캐릭터가 죽음, 메뉴에서 타이틀로 나감, 게임 창을 닫음, 게임 신호가 끊김, 패널 ■ 중지, 최대 판단. 끝난 이유와 층은 `config.json`의 `ended_reason`·`ended_depth`와 리포트에 남아요
   - `web.py`를 중간에 꺼도 게임은 멈추지 않아요. 기록창에 한 줄 뜨고 직접 이어서 할 수 있어요
- Python이 꺼져 있어도 게임은 멈추지 않고 **[AI 없이 시작]** 은 언제나 원작과 같이 돼요
- 잠깐 멈추려면 관찰 패널의 **⏸ 일시정지**: 입력 잠금이 바로 풀려 직접 조작하거나 힌트를 쓸 수 있고, **▶ 재개**하면 같은 판이 다음 판단부터 이어져요. 멈출 때 생각하던 판단은 버리고 다시 생각해요(비용은 합계에 더해요). 멈춘 시간은 `config.json`의 `pauses`에 남아요
- 판을 끝내려면 **■ 중지** (한 번 확인해요. 끝낸 판은 이어 갈 수 없어요). 급할 땐 **마우스를 화면 왼쪽 위 구석으로** 빠르게 옮기기
- **최종 목표**: AI 설정의 실험 옵션에서 [최종 목표]를 눌러 적어요. 비우면 기본 목표(지하 5층 보스 처치)를 쓰고, AI 입력이 글자까지 예전과 같아요. 바꾸면 `config.json`의 `final_goal`에 남고 패널·리포트에 보여요

**게임 ↔ Python 통로** (`/api/bridge/*`, 자세한 것: [bridge.md](../docs/project/bridge.md) 3장)
- 게임이 묻고 Python이 답해요: ① 상태 조회(3초마다) ② 키 보내기 ③ 연결 시험 ④ 판 준비 ⑤ 던전 도착 ⑥ 판 끝 ⑦ 살아 있음 신호(AI 판 동안 1초마다)
- 게임에서 시작한 판은 AI 입력 규칙 뒤에 `[이번 판]` 블록(직업, 켜진 제약 이름)이 붙어요. 시드는 넣지 않아요. `mvp.py` 판은 그대로예요
- Python은 키를 `.env`에만 쓰고 끝 4자리만 돌려줘요. 연결 시험 실패는 `reason`(`key_invalid`, `no_credit` 등)으로만 알려 줘요 (오류 원문에 키 일부가 섞일 수 있어서)
- 다른 웹사이트가 몰래 요청하지 못하게, `X-Nokpixel-Bridge: 1` 헤더가 있는 JSON 요청만 받아요. 통로 주소와 상태를 바꾸는 기존 주소(중지, 힌트, 창 배치 등) 모두 그래요
- 시험할 때는 `python web.py --env 시험용.env`로 실제 `.env` 대신 다른 파일을 써요

### 3. 두 창 관찰 화면 (게임 + 관찰 패널)
게임 창을 직접 나란히 놓거나 다시 클릭할 필요 없이, 두 창으로 실험을 진행하고 지켜봐요.
1. 게임을 켜고 던전 안까지 들어갑니다
2. `python web.py --panels` (데모: `python web.py --demo --panels`)
   - 관찰 패널이 주소창 없는 Edge 앱 창으로 뜨고(없으면 Chrome), 게임 창 오른쪽에 자동으로 배치돼요
   - 작업 표시줄을 뺀 영역 안에 놓아요. 게임 창이 그보다 크면 **⊞ 창 배치** 옆에 더 작은 크기로 실행하라는 안내가 나와요
3. 설정과 시작은 게임의 AI 설정 장면에서 해요(위 2번). 패널 아래에는 설정 요약 한 줄(읽기 전용)과 "게임의 AI 설정에서 시작해요"가 보여요. 패널에는 시작 버튼이 없어요

| 창 | 자리 | 내용 |
|---|---|---|
| 게임 | 왼쪽 위 | 세로 창. 실행 중에는 🔒 사람 입력 잠금. 제목 표시줄에 "잠김" 띠가 보여요 |
| 관찰 패널 (`/panel`) | 오른쪽 나머지 | 위: 상태(실행 중·생각만·끝남), 판단 n/최대, 비용, 게임 창 신호등, 최종·중간 목표, 지금 생각·행동·근거(남는 자리를 모두 씀, [기록 창에서 보기]), 준비 중 칸 / 아래: 전달 대기 힌트, 힌트 보내기·개입 횟수, 일시정지/재개·중지·창 배치·게임 창 앞으로·기록 창 열기, 실험 설정 요약(읽기 전용)·던전 도착 대기 표시. 판단 목록은 기록 창에서 봐요 |
| 기록 창 (`/log`) | 패널 위에 겹쳐 뜸 | 패널의 **기록 창 열기**(또는 지금 생각 옆 **기록 창에서 보기**)로 열어요. 판단 목록과 고른 판단의 목표·생각·행동·그때 AI가 본 화면. **닫으면 게임 창을 다시 맨 앞으로** 가져와요 (⬜ 실제 판에서는 미확인) |

**입력 잠금** (관찰 패널에서 시작한 실제 게임 판만)
- 막는 것: 게임 창 안에서 하는 사람의 클릭·휠, 게임 창이 맨 앞일 때 사람의 키 입력. AI의 키·클릭은 Windows가 "프로그램이 만든 입력"으로 표시해서 그대로 통과해요
- 막지 않는 것: 마우스 이동(다른 창 사용, 왼쪽 위 구석 비상 정지 가능), 다른 창에서의 키 입력
- 풀리는 때: 판이 끝남·중지·오류 / 일시정지(재개하면 다시 잠금) / `web.py`가 꺼짐 / **비상 해제 `F12`** (어느 창에서 눌러도 됨) / 마지막 수단 Ctrl+Alt+Del
- 잠금을 걸지 못하면 판은 그대로 진행하고 관찰 패널에 🔓와 이유가 보여요

**힌트 입력 중 대기**: 관찰 패널의 힌트 칸에 커서가 있는 동안 AI는 다음 판단을 시작하지 않아요(최대 60초). 게임 창이 입력 도중에 앞으로 튀어나오지 않게 하려는 것이에요. 보내면 바로 이어서 진행해요.

**게임 창을 못 가져올 때**: 키를 보내기 전에 게임 창이 맨 앞이 아니면 2초마다 다시 시도하며 최대 30초 기다려요(신호등 🟡). 관찰 패널의 **게임 창 앞으로** 버튼으로 다시 시도할 수 있고, 30초가 지나면 판을 멈춰요. 기다리는 동안 키는 보내지 않아요.

**신호등**: 🟢 입력 가능(게임 창이 맨 앞) · 🟡 기다리는 중(AI가 생각 중, 힌트 입력 중, 게임 창을 기다리는 중, 일시정지) · 🔴 멈춤(끝남·중지·오류)

**준비 중** (회색 자리만 있음): ⬜ 큰 점검 알림, ⬜ 제자리 경고(관찰자에게만), ⬜ 한 번만 실행, ⬜ 판단 간격, ⬜ 비용 상한, ⬜ 개입 뒤 AI 반응 강조, ⬜ 체력·층·배고픔, ⬜ 새 몬스터 알림, ⬜ 진행도 이정표 ○/51점, ⬜ 보스 처치 여부

## 화면

| 화면 | 주소 | 내용 |
|---|---|---|
| ① 실험 설정 (데모 전용) | `/` | 플레이어 이름, AI 모델, 공략 유무, 시드, 지난 판의 교훈, 최대 판단 횟수. `--demo`일 때만 열리고, 실제 모드에서는 관찰 패널로 넘어가요. 키 칸은 없어요 (키는 게임의 AI 설정에서) |
| ② 관찰 화면 | `/observe` | AI의 생각 카드(되새김·근거 포함), AI가 본 게임 화면 + 말풍선, 목표(최종·중간·실행), 기억 메모, 교훈, 토큰·비용, 개발자 개입 입력칸, 중지 |
| ③ 관찰 리포트 | `/report` | 되감기 막대(판단별 화면·생각·행동, 추측·큰 점검 표시), 통계, 중간 목표 변화, 기억 메모 추가·지움 순서, AI 분석 요약, 남긴 교훈·이어받은 교훈 |

생각만 하기 판은 관찰 화면과 리포트에서도 행동 옆에 `(실제로 실행 안 됨)`이 보여요. 기록 파일(`log.jsonl`)에는 따로 적지 않고, `config.json`의 `dry_run`으로 구분해요.

## 기록
`logs/run_날짜_시간_플레이어/` 폴더에 판이 하나씩 저장돼요. (GitHub에는 올라가지 않아요)
- `config.json`: 실험 설정. 10/31부터는 `display`(1440/1080/768/기타/데모), `game_window`(실제 잰 게임 창 크기), `ai_image`(AI 사진 크기)도 적어요. 이 칸이 없으면 이전 방식(가로 720×400) 기록이에요
- `log.jsonl`: 판단마다 생각, 행동, 말풍선, 중간 목표, 기억 메모, 받은 힌트, 토큰, 비용
- `step_001.png` …: 판단마다 AI가 본 화면
- `final.png`: 판이 끝난 뒤 화면 (마지막 행동의 결과. 교훈 쓰기에 사용, 실제 플레이만)
- `lessons.md`: 판이 끝나고 AI가 다음 판의 자신에게 쓴 교훈 (생각만 하기 판은 쓰지 않음)
- `inherited_lessons.md`: 이 판을 시작할 때 이어받은 교훈 (이어받았을 때만)
- `summary.txt`: 리포트에서 받은 AI 분석 요약

## AI가 받는 것과 내는 것

**받는 것**: 게임 화면 이미지(360×640, 게임 창이 더 크면 칸 평균으로 줄여요) + 최근 판단 5개 + 현재 중간 목표 + 번호 붙은 기억 메모 + (있으면) 개발자 힌트 + (공략 제공 시) 공략 문서 + (이어받으면) 지난 판의 교훈
- 생각만 하기 판에서는 최근 판단의 행동마다 `(실제로 실행 안 됨)`을 붙여요. 10/25 생각만 하기 테스트에서 AI가 기록 속 행동을 실제로 했다고 믿었기 때문이에요. 실제 플레이 판의 최근 기록 형식은 그대로예요.

**내는 것**: 생각(글) + 도구 하나
- `press_keys`: 키 최대 3개 (이동 wasd, 대기 space, 휴식 z, 탐색 e e 등)
- `click`: 화면 좌표 클릭 (360×640 사진 기준. 실제 창 크기에 맞춰 바꿔서 눌러요)
- 두 도구 모두 함께 적는 것
  - `speech`(말풍선), `goal`(중간 목표)
  - **되새김**: `check_goal`(이 행동 → 중간 목표 → 5층 보스가 어떻게 이어지나), `basis`(근거: 화면 / 기록 / 추측)
  - `memo_add`(기억 메모 추가), `memo_remove`(틀린 메모 번호 지우기, 예: M3)

**큰 점검**: 10번째 판단마다, 그리고 중간 목표를 바꾼 다음 판단에 최근 10개를 보여주고 "최종 목표에 가까워졌나 · 중간 목표가 맞나 · 틀린 메모는 없나"를 생각에 쓰게 해요.

**판이 끝나면**: 같은 모델이 이번 판 기록과 마지막 화면(마지막 행동까지 끝난 뒤 다시 찍은 화면)을 보고 다음 판의 자신에게 교훈을 써요 (`lessons.md`). 생각만 하기 판은 실제로 조작하지 않아 틀린 교훈이 나오기 쉬워서 쓰지 않아요. 다음 판 설정의 **지난 판의 교훈**에서 고르거나, 명령줄에서 `python mvp.py --lessons-from run_폴더이름`으로 이어받아요.

## 아직 안 되는 것 (게임 코드 연결 단계에서 추가)
- 체력·층·미니맵 같은 **게임 속 정보**를 글로 함께 주기 (지금은 화면 이미지만)
- **판단 요청**(`Hero.ready()`) 기준으로 AI 부르기 (지금은 매 행동마다 호출)
- **목적 단위 명령** ("(5,7)까지 이동") (지금은 키 입력 단위)
- 보스 처치 여부·도달 층·사망 원인 자동 기록
- 시드를 게임에 자동 입력 (지금은 기록용이라 게임에서도 같은 값을 넣어야 해요)
