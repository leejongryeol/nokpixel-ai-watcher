# 시스템 구조

## 전체 구조 (현재: MVP)

AI가 사람처럼 **게임 화면을 보고 키보드·마우스로 조작**한다. 게임 코드는 창 크기 고정 외에 건드리지 않았다.

```
┌──────────────────────┐   ① 스크린샷    ┌──────────────────────────┐   ② 이미지 + 글   ┌──────────────┐
│  녹픽던 게임 (Java)    │ ─────────────▶ │  ai-bridge (Python)       │ ───────────────▶ │  AI 모델 API  │
│  창 720×400 고정       │                │  agent.py                 │                  │ Claude/OpenAI │
│                      │ ◀───────────── │  · 화면 캡처 · 기록 저장     │ ◀─────────────── │  생각 + 도구   │
└──────────────────────┘   ④ 키·클릭     │  · 도구 → 실제 입력 변환     │   ③ 생각 + 행동   └──────────────┘
                                        └────────────┬─────────────┘
                                                     │ ⑤ 기록 (logs/)
                                                     ▼
                                        ┌──────────────────────────┐
                                        │  관찰 웹 화면 (web.py)      │  ← 관찰자(사용자)
                                        │  설정 → 관찰 → 리포트        │  ← 개발자 힌트·중지
                                        └──────────────────────────┘
```

| 구성 요소 | 파일 | 역할 |
|---|---|---|
| 게임 | `desktop/.../DesktopLauncher.java` | 녹픽던 원본. 창 크기만 720×400으로 고정 (스크린샷 비용 일정하게) |
| AI 플레이어 | `ai-bridge/agent.py` | 화면 캡처 → AI 모델 호출(Claude / OpenAI) → 키·클릭 실행 → 기록 |
| 관찰 웹 화면 | `ai-bridge/web.py`, `ai-bridge/web/` | 실험 설정, 실시간 관찰, 리포트·되감기 (내 컴퓨터에서만 접속) |
| 세 창 관찰 화면 | `web/now.html`, `web/console.html`, `ai-bridge/window_layout.py` | 창2 지금 AI는(`/now`), 창3 판단 기록·개입(`/console`). `python web.py --panels`로 Edge 앱 창으로 띄우고 게임 창과 함께 배치 |
| 입력 잠금 | `ai-bridge/input_lock.py` | 창3에서 시작한 실제 판 동안 게임 창의 사람 입력만 막는 별도 프로세스 (Windows 저수준 훅, AI 입력은 통과) |
| 명령줄 실행 | `ai-bridge/mvp.py` | 웹 화면 없이 콘솔에서 실행 |
| 공략 문서 | `ai-bridge/guide.md` | "공략 제공" 조건에서 AI에게 전달 |
| 기록 | `ai-bridge/logs/` | 판마다 설정, 판단 기록(`log.jsonl`), 스크린샷 (GitHub에 올리지 않음) |

## 한 번의 판단 흐름

1. **캡처**: 게임 창을 앞으로 가져와 스크린샷 (720×400)
2. **전달**: 스크린샷 + 최근 판단 5개 + 현재 중간 목표 + 기억 메모 + (있으면) 개발자 힌트 + (조건에 따라) 공략 문서. "생각만" 모드면 최근 판단의 행동마다 `(실제로 실행 안 됨)`을 붙인다 (AI가 기록 속 행동을 실제로 했다고 믿지 않게)
3. **판단**: AI 모델이 생각을 쓰고, 도구 하나로 행동 (생각을 받는 방식은 회사마다 다르다. 아래 "회사별 생각 전달 방식") (`press_keys` 또는 `click`, 말풍선·중간 목표·되새김(목표 연결, 근거)·기억 메모 추가/지우기 포함). 10번째마다, 중간 목표를 바꾼 다음에는 큰 점검을 요청
4. **실행**: 도구를 실제 키 입력·클릭으로 바꿔 게임에 전달 ("생각만" 모드면 생략). 게임 창이 맨 앞이 아니면 키를 보내지 않고, 2초마다 다시 가져오며 최대 30초 기다린 뒤 그래도 안 되면 판을 멈춘다
5. **기록**: `log.jsonl`과 스크린샷 저장 → 관찰 화면이 1초마다 읽어서 표시

1번 전에, 관찰자가 창3의 힌트 칸에 입력하는 중이면 다음 판단을 최대 60초 미룬다 (게임 창이 입력 도중 앞으로 튀어나오지 않게). 게임은 턴제라 기다리는 동안 게임 상태는 바뀌지 않는다.

## 세 창 관찰 화면과 입력 잠금

```
┌ 창1 게임 (왼쪽 위) ┐┌ 창3 판단 기록·개입 (/console) ┐
│ 🔒 사람 입력 잠금   ││ 설정·시작·중지·창 배치          │
└───────────────────┘│ 판단 목록(⭐ 개입) │ 상세+화면  │
┌ 창2 지금 AI는 (/now)┐│ 힌트 보내기                   │
│ 상태·신호등·목표·생각││                              │
└───────────────────┘└──────────────────────────────┘
```

- **입력 잠금** (`input_lock.py`): AI 쪽 작업과 따로 도는 별도 프로세스에서 Windows 저수준 훅(`WH_MOUSE_LL`, `WH_KEYBOARD_LL`)을 건다. pyautogui(`SendInput`)가 보내는 입력에는 Windows가 "프로그램이 만든 입력" 표시를 붙이므로, 표시가 없는 사람 입력만 막는다.
  - 마우스는 게임 창 안쪽의 클릭·휠만, 키보드는 게임 창이 맨 앞일 때만 막는다.
  - 풀리는 때: `Agent.run()`이 끝날 때(`finally`), 부모(`web.py`) 프로세스가 죽을 때, `web.py` 종료(`atexit`), 비상 해제 `F12`(조합키는 Ctrl·Shift가 먼저 막혀서 인식되지 않아 키 하나로 했다). 프로세스가 어떻게 끝나든 Windows가 훅을 자동으로 뺀다.
  - 별도 프로세스로 둔 이유: 훅 처리가 늦으면 Windows가 훅을 말없이 빼기 때문이다.
- **창3 시작**(`/api/console/start`)은 `.env`를 읽거나 쓰지 않는다. 기존 설정 화면의 `/api/start`는 그대로 `.env`에 모델·키를 저장한다.
- 세 창 화면은 `/api/state?since=n`으로 새 판단만 받는다. 신호등·잠금 상태(`phase`, `game_front`, `focus_waiting`, `locked`)는 화면에만 쓰고 `log.jsonl`에는 넣지 않는다.
- 화면에는 힌트가 "⭐ 개발자 개입"으로 보이지만, AI 입력의 `[개발자 힌트]`와 기록의 `hints` 칸은 그대로다 (실험 조건 유지).

판이 끝나면 화면을 한 번 더 찍고(`final.png`, 마지막 행동의 결과), 같은 모델이 기록과 그 화면을 보고 **다음 판의 자신에게 교훈**(`lessons.md`)을 쓴다. 다음 판은 이 교훈을 이어받아 시작할 수 있다. 생각만 하기(dry-run) 판은 조작을 하지 않아 틀린 교훈이 나오기 쉬워서 교훈을 쓰지 않는다.

## 회사별 생각 전달 방식

규칙(시스템 프롬프트)과 도구(`press_keys`, `click`)의 칸은 두 회사가 같다. 다른 것은 **생각을 어디에 쓰게 하느냐**와 **도구를 꼭 써야 하느냐**다. 이 차이는 `agent.py`의 `LLM` 클래스 안에서만 다룬다.

| | Claude | OpenAI |
|---|---|---|
| 생각 | 응답의 글(text) 부분에 쓴다 | 도구 입력 안의 `thought` 칸에 쓴다 (`_openai_tool()`이 칸을 추가하고 필수로 지정) |
| 도구 | 쓸지 말지 모델이 고른다. 안 쓰면 그 판단은 행동 없음 | `tool_choice="required"`로 반드시 하나 쓴다 |
| 이렇게 한 이유 | Claude의 기본 동작 | OpenAI 추론 모델(답하기 전에 속으로 생각하는 모델)은 도구를 강제하면 글 없이 도구만 부르는 일이 많아서, 생각을 도구 칸으로 받는다 |

**관찰 화면과 기록에 나타나는 모습**
- 두 회사 모두 생각은 `log.jsonl`의 같은 `thought` 칸에 저장되고, 관찰 화면의 "AI의 생각" 카드와 리포트의 "🧠 생각"에 똑같이 보인다. 화면만 봐서는 어느 회사인지 알 수 없고, `config.json`의 `model`로 구분한다.
- OpenAI는 응답 글(`output_text`)이 있으면 그것을 생각으로 쓰고 `thought` 칸은 버린다. 응답 글이 없을 때만 `thought` 칸을 쓴다.
- Claude가 글 없이 도구만 쓰면 생각이 비어서 "(생각 없음)"으로 보인다. OpenAI는 `thought`가 필수 칸이라 대체로 채워질 것으로 예상한다 (실제 빈도는 ⬜ 미확인).
- 그래서 생각의 길이·형식이나 "(생각 없음)"이 나온 횟수를 회사끼리 비교할 때는 이 차이를 감안해야 한다.

## 다음 단계 구조 (예정: 게임 코드 연결)

화면만으로는 체력·층 같은 정확한 정보와 판단 시점을 알기 어렵다. 게임 코드에 연결 지점을 추가할 예정이다.

```
녹픽던 게임 ── Hero.ready() 감지 ──▶ 게임 상태(JSON) ──▶ ai-bridge ──▶ Claude
     ▲          (판단 요청 + 이유)     (보이는 칸만)          │
     └──────────── 목적 단위 명령 ("(5,7)까지 이동", "휴식") ◀──┘
```

| 바뀌는 점 | 현재 (MVP) | 예정 |
|---|---|---|
| AI를 부르는 시점 | 매 행동마다 | 판단 요청이 생길 때만 (`Hero.ready()`, [판단 요청 문서](decision-points.md)) |
| AI가 받는 정보 | 화면 이미지 | 화면 이미지 + 게임 속 글 정보 (체력, 층, 주변 적, 가방, 메시지) |
| AI의 명령 | 키 입력 단위 | 목적 단위 ("(5,7)까지 이동", "체력 찰 때까지 휴식") |
| 결과 기록 | 판단 기록만 | 보스 처치 여부, 도달 층, 사망 원인, [진행도 이정표 점수](progress-milestones.md) |
| 게임 ↔ Python 통신 | 화면 캡처 + 키 입력 | 미정 (로컬 소켓 또는 파일) |

## 녹픽던 코드에서 사용할 지점 (예정)

| 코드 위치 | 무엇인가 | 용도 |
|---|---|---|
| `Hero.ready()` | 주인공이 다음 명령을 기다리는 순간 | AI 호출 타이밍 |
| `Hero.interrupt()` | 돌발 상황에서 하던 일이 끊기는 지점 | 판단 요청 이유 (A그룹) |
| `Hero.checkVisibleMobs()` | 새 적이 시야에 들어왔는지 확인 | 판단 요청 이유 |
| `HeroAction` | 이동, 공격, 줍기, 계단 이동 등 행동 목록 | 목적 단위 명령 |
| `Level.map`, `width`, `height` | 맵 지형 (한 줄 배열, `칸 번호 = x + y × width`) | 문자 지도 생성 |
| `Level.visited`, `mapped`, `heroFOV` | 가본 칸, 밝혀진 칸, 지금 보이는 칸 | 플레이어가 아는 칸만 전달 |
| `Mob.state` | 적 상태 (SLEEPING, HUNTING, WANDERING 등) | 적 정보 |
| `Char.HP`, `HT`, `Hunger` | 체력, 최대 체력, 배고픔 | 상태 정보 |
| `Belongings`, `Item.isIdentified()` | 소지품, 감정 여부 | 가방 정보 |
| `GLog` | 게임 메시지 로그 | 상황 설명 보조 |
| `Hero.die(cause)`, `Statistics` | 사망 원인, 도달 층 등 통계 | 관찰 리포트 |
| `Dungeon.seed` | 맵 생성 시드 | 같은 던전 재현 (AI에게는 숨김) |
